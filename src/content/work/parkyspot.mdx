## What it does

ParkySpot takes an ESP32-based parking signal and turns it into a simple real-time view of availability. The point is to close the gap between hardware readings and a usable place-finding decision.

## The constraint that shaped it

The data path was noisy and physically distributed, but the product had to remain understandable to a driver who wanted instant confidence, not a technical debugging dashboard.

The design treats the sensor feed as a noisy signal that gets normalized into a clear map state. This keeps the UI simple while preserving the fact that the underlying data is not perfect.

## What I built

I handled the prototype from signal capture to the user-facing interpretation layer. That included the sensor-to-application flow, the logic for turning raw state into a usable parking signal, and the interface for presenting it as an at-a-glance map.

## What I'd change

I would add stronger live-data quality checks and an explicit confidence indicator so users understand when a spot is likely stale, sparse, or degraded.
